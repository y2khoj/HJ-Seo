# Live Vault 3.8.2 — 최신 변경과 하울링 보호 검수

**3.8.2-preview / versionCode 20, personal 전용.** 검수 기준은 `codex/live-session-dashboard`의 최신 사용자 커밋 `572f2602514d87fe7db140ba7ca682a63be947fa`다. Sol (`gpt-6.1-sol`, medium)이 수정·테스트 코드를 작성하고 루트가 직접 소스·실행 결과·화면을 검수했다.

## 최신 변경 확인

`572f260`은 라이브 2×2 입출력, 위아래 리버브/에코 슬라이더, 어두운 설정 창, 상단 브랜드의 라이브 이동, 새 리버브/프리딜레이·스테레오 에코·컴프레서, 조용한 음성의 음정 감지 및 작곡기 리듬·검색·스크롤을 변경했다. 이 화면·기능을 되돌리지 않았다.

하울링 보호는 이번 사용자 커밋에서 새로 추가되지 않았다. `feedback_guard.h`는 기존 `969feb8`에서 도입된 상태였고, 최신 DSP 변경에서도 핵심 보호 로직과 엔진 적용 위치는 유지되어 있었다.

## 발견한 문제와 수정

| 검수 항목 | 기존 동작 | 수정 결과 |
| --- | --- | --- |
| 시스템 기본 출력 | mode 0에서는 보호를 끄지만 UI는 이어폰 없는 모니터링을 허용 | 네이티브 스트림의 실제 출력 장치 ID로 분류. 기본/알 수 없는 경로·스피커·불명확한 USB/A2DP는 보호 |
| 이어폰 연결 여부 | 연결된 장치와 실제 재생 장치가 다를 수 있음 | 실제 출력이 확인된 유선/USB 헤드셋·SCO/BLE 헤드셋·보청기에서만 우회. 장치 추가/제거·마이크 합류·경로 변경/롤백·서비스 갱신에서 재확인 |
| 같은 주파수의 반복 발생 | 기존 필터가 있으면 재발 처리를 조기 종료해 음소거 횟수가 증가하지 않음 | 새로운 음량 증가를 다시 판정하고 세 번 확인하면 실시간 출력을 음소거 |
| 저음역 필터 | 600 Hz부터 조사해 250/400 Hz 입력에 잘못된 필터가 잡히고 실제 감쇠는 거의 없음 | 약 150 Hz~8 kHz 균일 분석과 피크 보간으로 실제 주파수에 필터 적용 |
| 정상 저음 발성 오인식 | 검출 대역 안의 누설 에너지만 보면 낮은 음을 잘못 판정할 수 있음 | Hann 창의 전체 신호 에너지를 기준으로 단일음 집중도를 판정. 75/100/120 Hz 반복 상승도 잘못 음소거하지 않는지 검사 |
| 보호 해제·재연결 | 기본 모드 해제 시 출력이 100%가 될 수 있고, 경로 재개에서 사용자가 낮춘 값이 올라갈 수 있음 | 보호 경로 재시작은 18%, 경로 재개는 18% 이하로 제한하고 사용자의 조절 여부·보호 음소거를 유지 |
| 비정상 분석/출력 | 길이·비유한 수치 방어와 필터 초기화가 부족 | 분석 입력 범위 확인. 위험 경로의 잘못된 모니터 샘플은 양 채널 음소거·상태 유지, 제거된 필터 상태 초기화 |

배음이 있는 정상 발성·비브라토·숨소리·잡음의 오인식을 줄이기 위해 단일음 집중도와 연속적인 음량 증가를 함께 본다. 낮거나 중간 크기의 일정한 단일음은 자동 음소거 대상으로 삼지 않는다. 따라서 모든 종류의 하울링을 검출하거나 제거하는 알고리즘이라는 뜻은 아니다. 보호가 켜진 실시간 버스의 진폭 제한은 유지한다.

## 검증 결과

- 전체 개인용 Java/Robolectric **119개 통과**, 실패·오류·생략 0. [집계](validation/v3.8.2/java-counts.json).
- 전용 `scripts/test-feedback.sh` 및 `SANITIZE=1 scripts/test-feedback.sh` 통과. AddressSanitizer·UndefinedBehaviorSanitizer 오류가 없었다. [일반](validation/v3.8.2/feedback-host.txt) · [메모리 검사](validation/v3.8.2/feedback-sanitizers.txt).
- 44.1/48 kHz에서 250/400/1500/6000 Hz의 실제 감쇠, 동일 주파수의 세 번 재발, 좌우 음소거, 명시적 해제, 보호 우회/재개·스트림 재개 시 상태 유지, 조용한/지속 음·배음·비브라토·잡음·일시적 큰 소리, 잘못된 크기·NaN/Inf를 검사했다.
- 75/100/120/9000/12000 Hz의 검출 대역 밖 입력이 세 번 커져도 잘못 음소거되지 않는 검사를 추가했다. [결과](validation/v3.8.2/outofband-negative.txt).
- `test-native`, `test-v2`, `test-harmony`, `test-composer`, `test-schedule`, `test-arrangement`, `test-guitar-parity` 통과. 최신 DSP·화음·8트랙/목소리·예약·편곡·132개 기타 운지 회귀를 포함한다. 마지막 보호 변경 후 `test-native`도 다시 통과했다. [결과](validation/v3.8.2/native-regressions.txt) · [최종 오디오 검사](validation/v3.8.2/native-final.txt).
- 실제/요청 출력 불일치, 장치 정보가 없는 경우, 반주 재생 후 마이크 합류, 경로 롤백, 보호 음소거 중 녹음 유지, 보호 해제 시 모니터 복구와 효과값 유지의 Java 경로를 검사했다.
- 루트는 보호 처리의 위치도 직접 검토했다. 기록용 `recL/recR` 계산 뒤에 보컬·화음·목소리 악기의 `liveL/liveR`만 처리하고, 반주 `ml/mr`와 녹음 버퍼는 유지한다. 이는 실제 기기에서 녹음 파일을 확인한 실험을 대신하지 않는다.
- 루트가 현재 2×2 화면의 한국어 보호 상태와 영어 작은 창/130% YouTube 녹음 화면을 직접 검토했다. [렌더](screenshots/v3.8.2/). 오디오 상태·영상 영역은 격리된 fixture이며 실제 휴대폰 캡처가 아니다.

### 합성 단일음 비교

같은 입력에 첫 번째 필터를 적용한 뒤의 잔여 에너지/원래 에너지다. 실제 스피커와 마이크로 음향 루프를 만든 측정은 아니다.

| 입력 | 이전 잔여 에너지 (44.1/48 kHz) | 수정 후 (44.1/48 kHz) |
| --- | --- | --- |
| 250 Hz | 0.9992 / 0.9993 | 0.0160 / 0.0170 |
| 400 Hz | 0.9957 / 0.9957 | 0.0148 / 0.0145 |
| 1500 Hz | 0.0893 / 0.0891 | 0.0145 / 0.0144 |
| 6000 Hz | 0.1074 / 0.1041 | 0.0144 / 0.0144 |

이전에는 같은 1500 Hz가 세 번 커져도 음소거되지 않았고, 수정 후에는 세 번째 확인에서 음소거됐다. [이전](validation/v3.8.2/baseline-probe.txt) · [수정 후](validation/v3.8.2/fixed-probe.txt). 재현용 `tests/feedback_probe.cpp`는 기존 API만 사용해 이전/현재 헤더 각각을 include 경로로 지정할 수 있다.
