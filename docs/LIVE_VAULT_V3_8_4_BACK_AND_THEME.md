# Live Vault 3.8.4 — 친근한 라이브 화면과 뒤로가기 복구

**3.8.4-preview / versionCode 22, 개인용 APK.** `17c9642`의 작곡기 미니 LCD·코드 카드·이모지 채널 스트립을 유지하면서 라이브와 전체 메뉴에 같은 분위기를 적용했다. Sol (`gpt-6.1-sol`, medium)이 구현·테스트를 작성하고 루트가 코드와 렌더를 직접 검수했다.

## 사용자에게 보이는 변화

- 라이브의 마이크·모니터링·입출력·반주·보컬 효과·영상, 전체 메뉴에 관련 이모지를 추가했다. 기존 매트한 화면, LCD의 실제 상태·레벨·음정 표시와 승인 로고를 유지한다. 한국어·영어 모두 적용하며 사용자 파일명이나 프로젝트 데이터는 바꾸지 않는다.
- 메인 리버브·에코를 나란한 두 노브로 표시한다. **위로 드래그하면 증가, 아래로 드래그하면 감소**한다. 탭·가로 드래그로 값이 바뀌지 않고, 화면 가장자리에서 시작한 터치는 받지 않는다. 별도의 뒤로가기 제스처 제외 영역도 만들지 않는다. 키보드와 접근성 값 조절을 지원한다.
- 뒤로가기는 **맨 위 메뉴/팝업 닫기 → 이전 앱 페이지 → 이동 기록이 없는 라이브에서 앱 최소화** 순서다. 반주 소스 탭·보관함 필터와 이전 스크롤 위치도 되돌린다. 화면 재그리기나 현재 페이지 재선택은 이동 기록을 만들지 않는다. 재생성 시 현재 페이지와 기록을 복원하며 기록은 최대 128개다.
- 팝업 취소 시 미리듣기 되돌리기와 기존 취소·닫기 콜백을 유지한다. 녹화 화면을 떠날 때는 저장 확인을 거치고, 확인을 취소하면 페이지와 이동 기록을 유지한다. 일반 오디오 녹음과 마이크는 페이지를 뒤로 이동해도 유지한다.
- 녹음·카운트인 등 소스 변경이 잠긴 동안에는 뒤로가기로도 다른 반주 소스로 바꾸지 않는다. 잠금이 풀린 뒤 해당 기록으로 돌아갈 수 있다. 내 파일·작곡기·온라인과 라이브의 **반주 선택** 진입을 유지한다.

## 구현과 검수에서 확인한 점

기존에는 Activity 내부 페이지의 뒤로가기 처리가 없었다. 페이지 방문과 빈번한 화면 갱신을 분리하고, API 28의 기존 Back과 API 33 이상 `OnBackInvokedCallback`을 연결했다. Manifest의 application과 Activity에 현대 Back을 활성화한다. 현대 API는 `PRIORITY_DEFAULT`로 등록해 키보드의 시스템 처리보다 우선하는 별도 오버레이 우선순위를 사용하지 않는다. 네이티브 Dialog·PopupWindow는 각 창의 콜백으로 먼저 닫히며, Activity에도 열린 창 순서에 따른 처리를 둔다. 앱 코드에는 비공개 API 반사를 사용하지 않는다.

노브는 `SeekBar` 상속 없이 View로 구현한다. 가로 SeekBar의 자동 제스처 제외 동작을 피하며, 내부에서 시작한 세로 조작은 부모 ScrollView가 가로채지 않도록 한다. 리버브 0–100%, 에코 0–80%와 기존 효과 파라미터 저장을 유지한다. 상세 효과와 마이크·반주 볼륨, 전체 기기 음량 정책은 바꾸지 않았다.

루트 검수에서 발견해 보완한 경로는 다음과 같다.

1. 부모 ScrollView가 세로 노브 조작을 먼저 가져가는 문제: 실제 터치 전달 검사를 추가했다.
2. 레이아웃 전에 스크롤을 복원해 위치가 0으로 제한되는 문제: 다음 레이아웃에서 복원한다.
3. 온라인에서 내 파일로 돌아갈 때 YouTube 선택이 남는 문제: 승인된 화면 이동에서 소스 상태를 함께 정리한다. 자동 동영상 재생은 하지 않는다.
4. 녹음 중 이동 기록으로 소스 변경 잠금을 우회하는 문제: 상태 변경·기록 소비 전에 검사한다.
5. API 33에서 Activity에만 현대 Back을 활성화하면 콜백이 거부되는 경로: application에도 명시한다. 실제 플랫폼 dispatcher에 등록되는지 검사하며, Robolectric가 누락하는 Manifest opt-in 플래그는 테스트에서 실제 Manifest와 같은 값으로 설정한다.

Android 공식 참고: [현대 뒤로가기 처리](https://developer.android.com/guide/navigation/custom-back/predictive-back-gesture), [가장자리 제스처 충돌과 SeekBar 자동 제외](https://developer.android.com/develop/ui/views/touch-and-input/gestures/gesturenav).

## 검증 결과와 한계

전체 개인용 Java/Robolectric **147개 통과**, 실패·오류·생략 0. [집계](validation/v3.8.4/java-counts.json). 뒤로가기 15개에는 API 28 화면 이동·미리듣기 취소·소스 잠금·녹화 확인·재생성과 API 33/35의 실제 Activity/Dialog/PopupWindow dispatcher 콜백 호출이 포함된다. 노브의 수직/수평/탭/취소, 부모 스크롤 경유 터치, 접근성·키보드, 파라미터 저장 검사와 기존 반주 진입·작곡기·AI 파일 교환·영어·녹음·라우팅·하울링 경로 검사를 함께 실행했다.

한국어·영어 × 360×800/412×893 × 기본/130% 글씨에서 일반 라이브·YouTube 화면을 렌더하고, 고정 조작부·48dp 이상 조작 영역·겹침·스크롤과 YouTube 플레이어 최소 200dp 영역을 검사했다. 대표 [렌더 8장](screenshots/v3.8.4/)은 Android View의 native Skia 테스트 결과다. YouTube 이미지는 **OFFLINE fixture**이며 실제 영상 재생 검증이 아니다. LCD 음정·레벨·시간에도 테스트 입력을 사용한다.

실제 S26 Ultra의 가장자리 제스처·삼성 키보드·기기 오디오·YouTube 재생은 이 환경에서 검증하지 못했다. 애니메이션은 플랫폼 기본 동작을 사용하며 별도 페이지 전환 미리보기 애니메이션을 구현한 것은 아니다. DSP·하울링 보호와 개인용 캡처 오버레이는 이번 수정에서 변경하지 않았고, 기존 [실기기 미검증 항목](LIVE_VAULT_V3_8_2_FEEDBACK_REVIEW.md)은 유지한다.

개인용 APK·키·오버레이·전달 URL은 공개 Git에 포함하지 않는다. 기존 공개 standard APK는 교체하지 않는다.
