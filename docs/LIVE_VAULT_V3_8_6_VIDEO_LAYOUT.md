## 영상 링크와 화면

원인은 두 경로였다. 링크 선택이 현재 화면과 관계없이 라이브로 이동했고, 라이브는 YouTube 선택 시 LCD·볼륨 줄·효과 조작부를 별도의 축소 배치로 다시 만들었다. 또한 Android WebView와 HTML 플레이어 높이를 각각 220dp/220px로 고정했다.

- 온라인에서 링크를 불러오면 **온라인의 미리보기를 유지**한다. 이동 기록을 추가하지 않는다. 라이브는 사용자가 해당 이동 버튼을 누를 때 연다. 다른 링크를 선택해도 같은 동작이다.
- 선택을 완료하면 주소 입력 키보드를 닫는다. 잘못된 주소나 동의 취소는 입력 상태를 유지한다.
- 라이브의 LCD·입출력·마이크/반주 볼륨·반주 선택·보컬 효과를 공통 배치로 유지한다. 영상은 반주 카드 안에만 추가한다. LCD는 기존 151–300dp 가변 범위를 유지한다.
- 플레이어 높이는 `max(ceil(가용 너비 × 9/16), 200dp)`로 측정하고 HTML/iframe은 WebView의 너비·높이에 맞춘다. 좁은 화면에서 최소 높이로 생기는 여백은 공식 플레이어의 레터박싱에 맡긴다. 영상을 늘이거나 잘라 채우지 않는다. 200dp보다 좁은 창에서는 플레이어를 숨기고 창을 넓히라는 안내를 표시한다.
- 작은 창에서는 **본문을 스크롤**한다. 녹음 조작부는 하단에 고정한다. 영상 전체가 보이고 앱에 포커스가 있을 때만 재생을 허용하며, 일부 가림·탭 이동·배경 전환 때 일시정지한다. 다시 보인다고 자동 재생하지 않는다.

## 새 커밋에서 함께 보완한 회귀

- 힙합의 인덱스 8이 프로젝트 복사·저장 때 7로 제한되는 문제, 내보내기 이름 배열 및 JSON 스키마/가져오기의 누락을 수정했다. 힙합 저장·복제·AI 내보내기/재가져오기와 박자 호환성을 검사한다.
- 가상 건반에 음을 추가할 때 실제 음을 미리듣지 않으면서 네이티브 목소리 악기의 설정을 켜던 호출을 제거했다. 취소·저장·실행 취소와 다른 프로젝트를 연 뒤 남은 창에서 저장하는 경우를 검사한다.
- 에코 조절 창의 버튼 표시와 실제 값이 다른 문제를 수정했다. 에코는 실제 0–80%를 표시하고, ±5%는 5%포인트씩 변경하며 프리셋·표시·슬라이더를 동기화한다.

확장 패턴 중 일부는 같은 자동 연주를 공유하며 드럼 트랙의 새 패턴 선택은 현재 개별 반주 생성에 반영되지 않는다. 이번 수정에서 그 선택지를 새로운 연주 알고리즘으로 확장하지 않았다.
