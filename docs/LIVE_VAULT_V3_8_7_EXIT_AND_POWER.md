# Live Vault 3.8.7 — 종료 확인과 유휴 전력 사용 개선

`3.8.7-preview / versionCode 25`, 개인용 APK. [3.8.6의 영상 링크·레이아웃 수정](LIVE_VAULT_V3_8_6_VIDEO_LAYOUT.md)을 포함한다. 구현과 테스트는 Sol medium, 루트가 직접 코드와 검증 결과를 검수했다.

## 종료 동작

- 메뉴·팝업 닫기와 이전 페이지 복귀를 유지한다. 이동 기록이 없는 라이브에서 뒤로가기를 누르면 **종료 / 취소**를 묻는다. 전체 메뉴의 **종료**로도 접근할 수 있다. 취소하거나 확인창에서 뒤로가기를 누르면 기존 세션을 유지한다.
- 종료를 선택하면 녹음 파일을 닫고 마이크·반주·모니터링·YouTube·개인용 캡처·예약을 먼저 정리한다. MP4 결합, 진행 중이던 ZIP 쓰기와 프로젝트/화음 저장 작업이 끝날 때까지 기다린 뒤 실행 작업과 서비스를 정리하고 최근 앱 목록에서 제거한다.
- 완성된 프레이즈·화음의 저장을 반영하고, 미완성 연주 기록은 이전 완성본을 유지한다. 저장 실패는 확인창으로 알리며 원본을 임의로 삭제하지 않는다.
- 저장 중에는 새 조작과 중복 실행을 막는다. 늦게 도착한 권한 결과·가져오기 결과·재생 요청·이전 실행의 서비스 명령이 오디오를 다시 켜지 못하도록 한다. 다음 정상 실행에서는 새 세션을 복원하며 마이크나 재생을 자동으로 켜지 않는다.
- 프로세스를 강제 죽이는 `System.exit`/`killProcess`는 사용하지 않는다. Android가 빈 프로세스를 캐시할 수 있지만 종료 후 오디오 스트림·녹음·서비스·화면 갱신·CPU 깨우기 잠금이 남지 않도록 정리한다. 홈 버튼으로 이동하는 일반 백그라운드 녹음은 유지한다.

## 확인한 전력 사용 경로와 변경

실기기 배터리 수치만으로 원인을 확정한 것은 아니다. 코드에서 확인한 불필요한 동작을 줄였다.

| 경로 | 이전 | 변경 |
|---|---|---|
| 화면 유지 | 앱 시작부터 항상 켜짐 | 대기·단순 반주·보관함 등에서는 해제, 실제 라이브 표시/카메라 등에서만 유지 |
| 대기 UI 조회·갱신 | 80ms 간격 | 1초 간격, 백그라운드·종료 중에는 예약하지 않음 |
| 서비스 상태 조회 | 100ms 간격 | 250ms 간격 |
| 출력 경로 보완 조회 | 100ms 간격 | 500ms 간격, 장치 변경/소음 알림의 즉시 보호는 유지 |
| 연주 프레이즈 추적 | 20ms 간격 | 유지 |
| 반주 종료·일시정지 | 출력·서비스가 남을 수 있었음 | 실제 사용자가 없으면 스트림·서비스·알림·깨우기 잠금 해제 |

네이티브 `suspend()`는 기존 `stop(true)` 경로로 스트림과 분석 스레드를 쉬게 하면서 일시정지 위치를 보존한다. 일반 종료·오류·확정 앱 종료는 전체 정리를 사용한다. 반주의 자연 종료, 오래 남은 재생 요청 플래그와 기존의 제한된 정리 재시도도 검사한다. 효과 처리와 연주 소리를 UI 조회 주기로 생성하도록 변경하지 않았다.
